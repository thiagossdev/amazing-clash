# 2. Skill-Gem Simplification vs. Depth

[← Index](README.md)

This file is the single most directly relevant lesson in this pillar,
because it is GGG's own account of a fight between the same two goals
this project is trying to satisfy at once: real build depth, and a
system a new player can actually approach.

## The problem, in the developers' own words

Per [PC Gamer's group interview](sources.md): Path of Exile 1's build
customization was built on colored sockets (red/green/blue) on gear,
into which players insert skill gems. Colors had to match for a gem to
fit, which meant "the first roadblock for new players" and "a constant
bit of friction as you upgrade your gear," in the piece's own framing.
GGG designer Octavian is quoted directly: "I never really found socket
colors to be all that engaging of a system personally... I've had a bit
of an axe to grind for a number of years now." Game director Mark
Roberts frames the fix as being about letting people "who tried the
game and found it too complex to come back and try it again."

## The resolution

Search-corroborated coverage (see [sources.md](sources.md) for the
direct-fetch/search-synthesis distinction) describes Path of Exile 2's
skill gems as carrying their own support-gem sockets built in, removing
the socket-color matching step entirely while keeping the support-gem
linking concept that made the original system deep. The same
simplification later shipped back into Path of Exile 1 itself (the
Curse of the Allflame expansion, per PC Gamer), which is worth noting
on its own: GGG treated this as a genuine improvement to carry
backward, not a PoE2-only concession.

## Why this is the load-bearing lesson for this project

GGG's own account confirms depth and friction are not the same axis,
and removing friction did not require removing the underlying
support-gem depth: colored sockets were scaffolding around the
mechanic, not the mechanic itself. This project's own risk is
structurally identical: 50 classes, 500+ abilities, and a shared
build-space tree (per
[docs/research/eslabong-inspiration/02](../eslabong-inspiration/02-class-champion-and-ability-depth.md)
and [01](01-shared-passive-tree-and-class-identity.md)) is a lot of
raw content for a new player to approach, and the temptation is to
assume more content automatically means more friction. GGG's own
history says the friction and the depth can be separated and the
friction removed on its own. See
[05. Synthesis](05-synthesis-amazingclash.md) for what that implies
concretely for this project's own ability/build UI.
